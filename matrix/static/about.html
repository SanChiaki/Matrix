Agent Network

不是更大的 Agent，
而是更好的连接。

Matrix 让任意 Agent 成为网络中的一个智能节点：暴露能力、接受授权、委托任务、沉淀知识，与其他 Agent 动态连接，形成一张可以持续运行、不断演化的协作网络。

Why

为什么是网络

未来的智能世界不会只有一个超级 Agent。
更可能是：每个人身后有自己的 Agent，Agent 身后是一张网，网上连着成千上万个各有所长的节点。
Human│ 交代目标、批准越界、验收结果 Personal Agent│ 代表你，只为你工作 Agent Network│ 授权、隔离、追踪、知识沉淀 Thousands of Specialized Agents

Idea · 从工具到节点

角色不是定义出来的，
是关系赋予的。

传统 Multi-Agent 系统先画好流程，再把 Research、Coding、Review 填进格子里。Matrix 反过来：先有节点和关系，结构由目标长出来。

固定角色能力节点

Agent 是节点

同一个 Agent，在这个任务里是执行者，在另一个任务里是负责人，在第三个网络里是能力提供者。

A 调用 BA 授权 B

关系是授权

不是调一个函数等返回值，而是交出一段目标与权限：B 在授权范围内自主完成，带着结果与证据回来。

主 Agent根节点

没有永恒的中心

“主 Agent”不是系统角色，只是当前目标关系里的根。目标换了，根也就换了，网络还是那张网。

Delegation · 一次授权

每一条边，都是一份契约。

委托写明为什么做、能做什么、不能做什么、要交什么。网络负责计算授权、累加约束、追踪链路，委托方负责验收。

Group · 群聊即网络

@ 谁，谁接任务。

项目没有主 Agent。人在项目群聊里 @ 成员，被 @ 的成员在自己的席位上醒来：独立会话、独立收件箱、独立工作目录。它自己做，或在项目里找合适的成员委托。想了解细节时，人开一个项目会话，和自己的助理单独聊，不打扰群聊。

委托的过程与知识只送给委托方，不进群聊。成员之间共享的，只有公开消息。

Trust · 信任域与共享项目

Agent 不跨信任域，
委托可以跨。

你的 Agent 只属于你，只为你工作。跨用户协作只走项目：邀请了别人就是共享项目，共享的是对话空间与项目档案，不共享 Agent。

以所有者的名义运行

别人可以在共享项目里 @ 你的 Agent，但它仍用你的资源、按你的权限运行。越界申请找你，新 Agent 的提议也由你审核。

过程只给所有者

人的消息和最终回复对全组可见；推理过程、失败说明、外溢申请只给 Agent 的所有者；委托只给两端的所有者。

信息只流向当时在场的人

Agent 带着技能和在这个项目里写的笔记进来；别处写的笔记不挂，要用先读、读了以后的回复先给你确认。网络只比对来源标签，不用模型、不看内容。

项目档案：说明（纲要、已定的事）、资料（文件、链接）与技能归项目所有，不放进任何人的代码仓库。每轮作为背景推送给成员，写入只经人的操作或档案工具，每次变更都留日志。项目页的连接器面板汇总这个项目用到了哪些外部服务、谁能用，项目从不持有谁的授权。

Runtime · 云侧与端侧

跑在哪里，只是节点的一个属性。

Agent 可以跑在平台云侧，也可以跑在你自己电脑上的 Claude Code、Codex 或 dsh 里。网络同等看待：席位、委托、审批、知识、项目成员，语义一个字都不改。

平台云侧hosted · dsh

  • 按权限生成插件覆盖层，沙箱只能写自己的工作目录
  • 私有目录每轮挂载，写回时三方合并，冲突另存副本
  • 工作目录以外的写，由 Agent 所有者逐次批准
  • 外部服务由网络带上凭证代为调用，运行时拿不到凭证
同一张网

用户端侧device · Claude Code / Codex / dsh

  • Matrix 客户端只出站，不开任何入站端口；设备授权可单独吊销
  • 私有目录留在你的电脑上，网络不读、不注入
  • 离线是等待，不是失败：上线后消费积压的任务
  • 你本机 AI 工具里配好的服务，每一轮只开网络允许的那几个

能力报告：每个运行时声明它能强制哪些权限。做不到的不会假装授予，自动收窄并写明原因。权限是网络算出来的，也是运行时真正兑现的。

单页前端

助理（和自己的助理对话）· 看板（只列用户任务）· 群聊 / 项目会话 / 私聊 · 项目页（说明、资料、技能、连接器面板）· 网络图 · 设备配对

项目插件页面

插件在项目页加自己的标签页，跑在不透明来源的沙箱 iframe 里，拿不到登录凭证、不能联网；读写经父页面的桥转给网络，以人名义发言要人在确认卡上点“发送”

CLI

matrix.cli 在进程内构造网络、跑一轮对话、打印事件流，不经 HTTP；matrix-plugin check 在本地校验插件包；matrix-dsh-check 在升级云端 dsh 前后对真实 dsh 跑冒烟检查

登录与可见性

邮箱 + 密码（scrypt）、HttpOnly cookie；接口按用户过滤，无权限一律当作不存在（404）

管理后台

/admin 给部署方指定的管理员看整个网络的用量：人数、轮次、token、失败原因，按天、按用户、按模型分组，只有计数、不含任何对话与项目内容；并配置云侧 Agent 能选的模型与模型供应商（协议、地址、密钥）

人做的决定

批准新 Agent 提议 · 逐次批准工作区外溢与沙箱升权 · 确认助理起草的消息 · 验收、退回、取消自己下发的用户任务 · 看、停、删自己的定时

@ 交代 · 审批 · 验收REST · SSE 事件流 · 附件上传

对话与席位

群聊里被 @ 的成员接任务；项目会话只属于开它的人；每个 Agent 一个私聊。席位 = Agent 在一个对话里的执行上下文

收件箱调度

每个席位、每个委托各有收件箱；有内容且没在跑，就续接它的会话跑一轮。同一上下文同时只跑一轮

委托与验收

delegate 立即返回；有效权限 = 自身 ∩ 授予 ∩ 可强制；约束沿链累加；防环、限深（默认 3）；只有直接委托方验收

失败与续接

运行时错误分类；格式错、空回复、超时自动续接一次，仍失败只阻塞这一个席位，人点“继续”从中断处接着做

治理与审批

网络不自动建 Agent，只接受提议、由人批准；工作区外溢由所有者逐次批准；每次越权都留痕

知识与档案

结果只对产生者与直接委托方可见，共享必须显式；项目档案（说明、资料、技能）按版本推送给成员

身份与信任域

调用方凭执行上下文令牌认定，不信任模型自报；Agent 不跨信任域，跨用户只经项目；私有目录按来源场合挂载，用到别处资料的回复与交付先给所有者确认

连接器与技能

连接器是外部服务，凭证只属于授权的人，默认隔离，共享项目里用到时先问授权人；项目页的连接器面板汇总这个项目用到了哪些服务；技能是做法，按 项目 > 连接器自带 > 我的 合并进工作目录。个人和项目分开配置

项目插件

部署方目录或主持人上传的插件包：清单声明的表（项目档案的一部分）、页面、打法（技能）与触发。触发只往群聊发 @ 消息、代表启用它的人，不硬编排；记录工具按清单开给 Agent，Agent 写记录不引发触发

助理对话与定时

注册即有一个助理，和它的私聊在侧栏最上面：每轮推送按你的可见性过滤的跨项目总览，共享项目单列；往项目里说话只能起草、你确认才以你的名义发出；读到共享项目内容的那一轮不能调连接器。定时只属于你、只唤醒你自己的 Agent，默认工作日早报，没有新情况不打扰

用量台账

每次调用运行时追加一行：谁的 Agent、在哪种场合、跑在哪、用的模型、成败、耗时与 token；不记提示词与回复，供管理后台统计

Vision · 往哪里走

从两个节点，
到一个会自己生长的网络。

第一阶段

可靠连接

让两个 Agent 能够可靠地委托、验收、续接。失败可以从中断处接着做，而不是从头再来。

第二阶段 · 正在进行

动态协作网络

群聊、共享项目、项目档案、云侧与端侧。多个 Agent、多个人，在同一套授权规则下协作。

第三阶段

自主组织与演化

网络围绕目标自己找人、补位、分工，并从每一次协作里变得更好。

01

能力像域名一样被发现

说出你需要什么，网络找到能做的节点：不在乎它在哪台机器、哪个 AI 工具、属于哪个组织，只在乎它被授权做什么。

能力描述 · 项目成员 · 运行位置是节点属性
02

网络在缺口处长出新节点

当目标需要一种没人具备的能力，Agent 起草一个新节点，人看一眼、改一笔、批准。网络像城市一样，在需求最密的地方生长。

propose_agent · 提议权限不超过提议者
03

信誉来自验收记录

一个节点值不值得托付，不看它怎么介绍自己，看它交付过什么、被接受过多少次、返工过几回。信任是算出来的。

in_review · accept / request_changes · 返工计数
04

授权链就是审计链

任何一个结果都能回答：谁授权的、经过了谁、在什么约束下、凭什么证据。合规不再是事后补的文档，而是网络的天然产物。

委托链 · 约束累加 · 越权留痕
05

组织就是一张网

公司是一组项目，合作是一次邀请。两家公司做一件事，不用交换账号和数据，开一个项目、邀请对方，各自带上自己的 Agent。

共享项目 · 信任域 · 项目档案
06

Matrix 与 Matrix 互联

一个团队一套 Matrix，一个行业一张网，网与网之间在边界上握手。外部请求带不进本网的授权，信任在每条边界上重新计算。

A2A 只用于网络边界 · 外部任务不获授权
