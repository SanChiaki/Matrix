# 业务系统对接 Matrix（演示）

一个模拟的业务系统「报销系统」，把业务系统对接 Matrix 能用的能力全部真的调一遍，给要对接的业务系统团队演示用。
接口说明与检查清单见 [对接指南](../../docs/open-api-integration.md)，设计见 [open-api.md](../../docs/open-api.md)。

```
浏览器 ──> biz_system.py（报销系统的后端，令牌只在这里）──Bearer mat_…──> Matrix /open/v1/*、/svc/*
                                                                          │
                     系统账号登录 Matrix 网页 /system（只读）<──────────────┘
```

## 跑起来

```bash
uv run python examples/business-system/setup_demo.py
```

```bash
uv run matrix --runtime scripted --data .matrix-biz-demo --plugins examples/plugins.json
```

```bash
uv run python examples/business-system/biz_system.py --config .matrix-biz-demo/biz-system.json
```

打开 http://127.0.0.1:8800 。重来一遍：`setup_demo.py --fresh`，或者在页面上执行“清理”再“清空本地记录”。

`setup_demo.py` 只准备“业务系统来对接之前，公司里已经有的东西”：管理员登记的应用「报销系统」与它的业务系统账号（负责人 maya）、
令牌、网页登录；五个 Agent——公共 Agent「财务助手」「票据核验」「法务顾问」（ops 维护），ann 的「合同审核」、ben 的「预算管家」
（两人都开放给了这个应用）；部署方目录里的模板「报销审核小组」与插件；
maya 发布、点名给报销系统用的服务「差旅咨询」；ann 代表她自己签的个人令牌（只有“查”）。
项目、资料、技能、服务都由报销系统接入以后经接口自己建，演示时一步步点出来。

Agent 用的是脚本运行时（`matrix/scripted.py` 的“业务系统对接演示”一节），回答是固定的，不调模型，离线就能演示。

## 多 Agent 协同

报销系统建的项目「报销审核」里是五个 Agent，服务的入口是「财务助手」，另外四个是岗位（能被委托的）：

```
财务助手（入口）
├─ 票据核验     校验发票真伪与金额
├─ 预算管家     查部门预算余额（ben 的个人 Agent）
└─ 合同审核     核对合同条款（ann 的个人 Agent）
   └─ 法务顾问  合同审核看到违约条款，再转给它（第二层委托）
```

5000 元以下的报销单财务助手自己给结论；5000 元以上的分头交给票据核验和预算管家，附合同的再交给合同审核。几位同时在做，
每交来一份财务助手就验收，说一声还在等谁，都到了才给汇总的结论。调用方在流里看到的：每一份委托与它的状态（`progress` 的 `task`）、
每位在说什么、调什么工具、没动静时的心跳；页面把这些拼成一棵“协作”树（谁交给了谁、每块到哪一步、谁正在做什么）。

这都是 Matrix 网络在做：委托只能给项目成员与服务的岗位、权限沿委托链只收窄（法务顾问拿不到委托权限）、只有直接委托方能验收、
过程按调用方的可见性给出。脚本运行时里这些 Agent 的说法是固定的，换成真实运行时（`uv run matrix`）就是模型自己决定怎么分工。

## 演示怎么讲

**第一页「对话」：员工直接和 Matrix 上的服务聊。**

1. 左上角选服务：「差旅咨询」是别人发布、点名给报销系统用的，一开始就能聊；「报销审核」是报销系统自己的，先点“一键准备”发布。
2. 随便问，例如“去上海出差住宿标准是多少？”、“BX-2001 技术咨询费 12,000 元，附合同，请审核”。附合同的那条能看到
   **多 Agent 协同**：回复上面的“协作”树实时变化（四份委托、两层），下面的“过程”列出每一步；做完后过程收起，只留结论。
3. 接着问（“依据是什么？”）就是续接同一个服务会话（报销系统带上 `session_id`）；“新对话”新开一个会话；正在做时能“中断”。
4. 左边列着这次打开页面以来的对话，每个对应 Matrix 上的一个服务会话（系统账号在 Matrix 的只读页面里也看得到它们）。

**第二页「报销单」：业务系统把自己的数据送去审核。**

1. 点“一键准备”：报销系统按顺序调 查 Agent → 建项目 → 角色 → 资料 → 可见范围 → 技能 → 发布服务。
2. BX-1001（280 元）提交审核：入口「财务助手」读了报销制度，直接给结论。
3. BX-1002（12,000 元，附合同）提交审核：财务助手分头交给票据核验、预算管家、合同审核，合同审核再转给法务顾问；
   协作树上能看到每块的进度，法务顾问十几秒不出声时有一条**心跳**（还在做：合同审核、法务顾问 · 15 秒）；最后是汇总的结论。
4. 出结论后在下面**追问**“依据是什么？”：带着 `session_id` 续接同一个服务会话，入口记得前面的事。
5. BX-1003（批量 8 张发票）提交审核，中途点**中断**：流里收到 `error`（被人终止），会话保留，再问能接着做。

**第三页「对接能力」：开发者要看的。** 左边每一步是一个接口，点“执行”就真的调一次，右边列出请求、状态码、响应。

| 层 | 步骤 | 接口 |
| --- | --- | --- |
| 查 | 能用的 Agent、能用的模板、代表个人时查到的不一样 | `GET /open/v1/agents`、`GET /open/v1/blueprints` |
| 组 | 建项目（开放的 Agent 拉进来，所有者成为参与者）、改描述与角色、增减成员、上传资料、资料的可见范围、项目技能、装插件、用模板建项目（先 409 确认、带 digest 再来）、它能管的项目 | `POST/PATCH/DELETE /open/v1/projects…` |
| 发 | 发布服务、改服务（版本 +1） | `POST/PATCH /open/v1/projects/{id}/services…` |
| 调 | 服务名片、调用自己的服务（流式）、续接、调用别人的服务、看用量 | `GET /svc/agents/{s}`、`POST /svc/agents/{s}/chat`、`…/usage` |
| 看 | 系统账号登录 Matrix 网页 `/system`（只读）：它调用服务的会话、它发布的服务的用量 | 网页 |
| 错误处理 | 没有 scope → 403、认不出的令牌 → 401、看不到的 → 404 | |
| 清理 | 撤回服务、删项目（只能删经这个应用建的） | `DELETE …` |

“按顺序全部执行”跑除了清理以外的每一步。中断在第一页演示（要一个正在跑的会话）。

**在 Matrix 里看**：页面右上角“在 Matrix 里查看”，用 `setup_demo.py` 打印的系统账号邮箱和密码登录，是只读页面；
负责人 `maya@demo.local`（密码 `demo-pass-123`）用自己的账号登录，项目「报销审核」里她等同主持人，看得到群聊里“（经「报销系统」）”的留痕。

## 文件

| 文件 | 是什么 |
| --- | --- |
| `setup_demo.py` | 搭 Matrix 这边的演示数据，写出报销系统的配置 `<数据目录>/biz-system.json`（Matrix 地址、令牌、系统账号的登录） |
| `biz_system.py` | 报销系统的后端（只用标准库）：每个能力一步（`BizSystem._define_steps`）；对话与送审走 `/api/chat`，把 Matrix 的 SSE 原样转给浏览器 |
| `static/` | 报销系统的页面：对话、报销单、对接能力 |
| `materials/` | 报销系统上传进项目的资料（报销制度、合同模板），以及「差旅咨询」用的差旅标准 |
| `blueprint/` | 模板「报销审核小组」：两个角色（接待、合同），管理员放进部署方目录 |

测试 `tests/test_business_system.py` 用真实 HTTP 把每一步走一遍，演示坏了会变红。

## 换成真实的业务系统

- **令牌只在服务端**：演示读的是一个 JSON 文件，真实系统放进密钥管理；浏览器、移动端拿不到。
- **读超时要长于 15 分钟**：`/svc/…/chat` 等到这一串做完才结束。
- **处理 `progress`**：显示“交给谁了、在做什么”，不认识的 `kind` 跳过；最终结果以 `done` 为准。
- **要确认的操作**（用模板、装插件）：第一次 409 + `{confirm, digest}`，给人看过再带 `digest` 来。
- **401 告警找管理员重签，403 是令牌没授权那个 scope，404 是看不到（不是网络错误），429 是每分钟超过 600 次。**
- 入口把活委托出去时，它那一轮说的“已交给合同审核”要等下一条回复来了才以 `delta` 送出（流不知道那一句是不是最后一句）；
  在那之前，看 `progress` 里的委托。
