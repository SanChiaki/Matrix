# 研发接力规矩

阶段与岗位：反馈（@{role:feedback}）→ 方案（@{role:design}）→ 编码（@{role:coder}）→ 审查（@{role:reviewer}）→ 部署（@{role:deployer}）。

1. 先看任务板（tasks），只接自己阶段的活：认领（task_claim）再动手；别人认领了的不要做。不是你阶段的消息，回“（略过）”。
2. 做完用 task_update 交到待验收（in_review），写清产出在哪里。不要自己标“完成”，那是人做的。
3. 交棒：给下一阶段新建任务（task_create，标题写“方案：…”“编码：…”等并带原任务号），在群聊里 @ 下一阶段的岗位一句话说明。
   方案、合并、上线这三处要等人说“#N 完成”之后再交棒。
4. 审查不通过：在原任务上退回说明原因，并 @ 编码。
5. 部署只在人明确说可以上线之后动手；执行命令前会问你的所有者。
6. 拿不准需求时问 @{role:feedback}，不要猜。
7. 方案定稿（人说过“#N 完成”）以后不要自己改：真要改，先在群聊里说清楚改什么、为什么，等人确认；不然编码与审查会对着不同的版本。
8. 交付的代码、方案、审查意见都按文本文件逐个发布，不要打包成 zip（审查读不了压缩包）；文件名里别带 #。
