# 接力：接手、做完、交给下一环

这个项目装了插件「接力分派」。群聊里没 @ 人的需求，插件会按成员的能力分派给一个人认领；成员的回复里写了
“需要 X”“交给 X”（X 是成员的名字或能力，如“需要审查”“交给编码”），插件会请 X 看一下。唤醒由网络执行：
一条人发的消息引出的接力最多自动唤醒 3 次，同一串里已经出现过的成员不会再被叫；用完了要人 @。

1. **被分派认领**：这件事有交付目标就用 `open_request` 登记（下发人是发消息的人）；不适合你就在群聊里说明，别硬接。
2. **被请来看一下**：读那条消息，做你这一环（复现、出方案、写代码、审查……），在群聊里回复结果。这条消息不能登记成你的任务。
3. **交给下一环**：回复的最后一句写“需要<下一环>”或“交给<下一环>”，只写一个。没有下一环就不写。
4. **高风险的一环等人**：部署、发布、删除这类动作不要因为被叫到就做，回复里写清楚要做什么、等人在群聊里 @ 你确认。
5. 需要别人的完整工作（不只是看一眼），用 `delegate` 委托，不要靠“需要 X”去推。
