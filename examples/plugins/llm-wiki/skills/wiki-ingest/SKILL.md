# 把资料编进项目 Wiki

项目 Wiki 由插件「项目 Wiki」托管（plugin 填 `llm-wiki`，工具用 `plugin_call` 调，参数写成 JSON 字符串；第一次用先 `plugin_tools` 看一遍）。
目录每轮会推给你；整份 wiki 的只读副本在 `./plugins/llm-wiki/wiki/`，可以直接读文件。
做法参照 Karpathy 的 LLM Wiki 模式：原始资料不可变，wiki 是从原始资料编译出来、由你维护的一层。

## 步骤

1. **存原始资料**：`wiki_add_source`（topic、slug、title、content 放全文，source 写出处：项目文件名、网址或“某某的交付”，published 写资料自己的日期）。
   资料来自 `./project/` 里的文件时，content 照原文放进去，不要先改写。存进去就不能再改。
2. **分诊**：先 `wiki_search` 找资料里的关键实体和它们的别名，决定这份资料属于哪种情况（可以同时有几种）：
   - 新内容：wiki 里还没有，开新页面；
   - 补充：已有页面要更新；
   - 有冲突：和已有页面的说法矛盾，两边都标出来，不要悄悄改掉旧说法；
   - 没有新东西：只用 `wiki_log`（op=ingest）记一笔，结束。资料太薄就不要硬写页面。
3. **编页面**：`wiki_write`（path 写 `<主题>/<名字>`，op=ingest 或 update，summary 是目录里的一句话）。每页的格式：

   ```
   # 标题

   > 来源：<作者或出处>；原始资料：[标题](../../raw/<主题>/<文件>.md)；更新：YYYY-MM-DD

   正文：结论在前，事实带出处。

   ## 相关
   - [另一页](../<主题>/<名字>.md)
   ```

   **数字、日期、原话必须和原始资料一字不差**（写 42K 就是 42K，不要改成 4.2 万）；算出来的数要写出怎么算的。
   `wiki_lint` 会逐个核对页面里的数字能不能在它引用的原始资料里找到。
4. **级联**：再搜一遍这份资料影响到的说法，逐页更新。被取代的说法留着，标上“（已过时，YYYY-MM-DD 起见 …）”，不要直接删掉历史。
5. **收尾**：`wiki_write` 会自动更新目录和日志；最后在群聊里用一两句话说明新建了哪几页、改了哪几页、有没有冲突要人定。

## 验收后写回

网络在一个用户任务被验收后会 @ 你写回。写回的只能是交付里**经过验收**的结论：把交付说明当作一份原始资料存进去（source 写“<任务标题> 的交付，<日期> 验收”），
再按上面的步骤编进页面。没有值得长期保留的东西就只记一笔日志。
