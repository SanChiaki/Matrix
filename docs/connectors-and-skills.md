状态：**草案，待定**。只做方案，不改代码。相关设计：[device-runtimes.md](device-runtimes.md)（运行时、端侧驱动）、

约束：[AGENTS.md](../AGENTS.md)、[invariants.md](reference/invariants.md)、[security.md](reference/security.md)。

## 1. 要解决什么

Agent 现在能做的事只有两个来源：运行时自带的工具（搜索、读写文件、命令行，按权限关开）和网络工具（委托、档案）。
缺两样东西：

- **连到外部服务**：让 Agent 读写飞书文档、日历、邮箱、GitHub、数据库……要授权，动的是某个人的数据。
- **可复用的做法**：一个团队怎么写周报、怎么做竞品分析、怎么排查线上问题。不连任何外部服务，是一段说明（可带模板、脚本）。

这两样东西性质不同，作为**两个并列的用户概念**：

| | **连接器** | **技能** |
| --- | --- | --- |
| 是什么 | 一个外部服务的接入：飞书、GitHub、某个数据库 | 一种做法：说明 + 可选的模板 / 脚本 |
| 需要授权 | 要，凭证属于授权的那个人 | 不要 |
| 动的是 | 授权人在外部服务里的**状态**（数据、账号） | Agent 的**能力**（怎么做） |
| 用户看到 | 名字、一次“授权”、一个开关、状态 | 名字、一句描述、正文 |
| 用户看不到 | 底下是 MCP 还是命令行工具、凭证怎么存、怎么续 | — |

连接器可以自带技能（例如飞书连接器带“写飞书文档”“排日程”的做法），技能不依附于连接器。
命名与“盖住传输与认证”参照 WorkBuddy 的连接器（research: workbuddy#connector-model）；
个人授权 / 公共授权的取舍见下文第 4 节（research: workbuddy#connector-auth）。

划分依据是 CHARTER 的“能力共享，状态隔离”：**技能是能力，可以随 Agent 和项目共享；连接器背后是某个人的状态，
默认隔离，只能显式放开。** 个人配置和项目配置分开，各管各的。

## 2. 两个层级

| | 个人（我） | 项目 |
| --- | --- | --- |
| **连接器** | **我的连接器**：我授权的服务，凭证属于我。我勾选我的哪些 Agent 能用 | **项目需要的连接器**：项目声明“这里要用飞书文档（某个空间）”，不持有凭证。每个成员 Agent 用**它所有者自己的**授权 |
| **技能** | **我的技能**：我维护的技能库，勾选给我的 Agent<br>**Agent 自己攒的技能**：Agent 写在私有目录里，网络不读 | **项目技能**：项目档案的一部分，归项目所有，所有成员 Agent 在这个项目里都能用 |

一句话：**个人层管“我有什么”，项目层管“这里需要什么、这里怎么做”。** 项目层从不持有任何人的凭证。

### 2.1 我的连接器

- **在哪授权**：
  - 云端：在网页里授权（填 Key 表单或 OAuth 跳转），凭证由网络加密保存。
  - 我的电脑：凭证留在我电脑上，Matrix 客户端只上报“这台电脑上有：飞书（已登录）”这类名字与状态，不上报凭证
    （和现在端侧的做法一致：凭证与模型密钥都留在用户电脑）。
- **给谁用**：每个连接器勾选我的哪些 Agent 能用。新授权时默认只勾我的助理。
- **三种状态分开显示**（参照 WorkBuddy 的绑定 ≠ 启用 ≠ 连得上）：
  - **已授权**：有凭证。
  - **已开启**：某个 Agent 在某个地方可以用。
  - **可用**：这一轮实际连上了。
  - 例如授权过期，显示“需要重新授权”，而不是让 Agent 一直失败。
- **联合项目里默认关**：我的 Agent 在别人主持的联合项目里，默认**不能**用我的连接器，要我在这个项目里逐个打开。
  打开方式和现在的“挂载私有目录”开关一样（`set_home_mount`）。理由：联合项目里是别人 @ 我的 Agent，
  动的却是我的数据，结果还会写进大家都看得到的群聊。
- **只有我看得到**：连接器的存在、授权账号、调用记录都只给授权人看（不变量 13）。别的参与者只能看到“满足 / 未满足项目需要”。

### 2.2 我的技能与 Agent 自己攒的技能

技能分两种，区分点是**谁写、网络读不读**：

- **我的技能（技能库）**：
  - 人在界面里维护，存在 `users/<uid>/skills/<名字>/SKILL.md`（可带同目录的模板、脚本）。
  - 在 Agent 设置里勾选这个 Agent 用哪些。
  - 技能是能力，跟着 Agent 走：在联合项目里也照样带着。正文不会给别的参与者看，但 Agent 按它做出来的结果大家看得到。
- **Agent 自己攒的技能**：
  - Agent 在自己私有目录的 `skills/` 下写的，网络不读、不列出、不改（不变量 8）。
  - 私有目录挂载了它就在，没挂载就不在。联合项目里私有目录默认不挂载，所以默认也没有这部分（不变量 16）。
  - 人想把它变成“我的技能”，可以从 Agent 的工作目录里看到后手动收进技能库。网络不会自动抽取。

### 2.3 项目需要的连接器

项目层**不做公共授权**。WorkBuddy 的公共授权是管理员配一套凭证、成员共用；放到 Matrix 的联合项目里，就是别人的 Agent
用主持人的账号读写主持人的数据，跨了信任域（不变量 16），也会把权限放大到那个人自己没有的范围（不变量 1）。

项目层只做**声明**：

- 项目配置里写“本项目需要：飞书文档，用途：共同维护需求文档，范围：某个文件夹”。范围就是一条资源引用（`refs`），
  引用依旧只是指针，不授予访问权限。
- 成员面板按 Agent 显示是否满足：
  - **就绪**：所有者授权过，并且在这个项目里打开了。
  - **未授权**。
  - **未打开**。
  - 只显示状态，不显示是谁的账号。
- 内部项目只有所有者自己，声明只起提示作用：所有者的连接器按 Agent 的勾选直接生效。
- **要用别人的连接器，就委托别人的 Agent**：B 没有飞书授权，需要读 A 的飞书文档时，B 的 Agent 委托 A 的 Agent，
  A 的 Agent 用 A 在这个项目里打开的连接器去做，结果按委托交付。这是现有机制，不需要新概念：凭证不出 A 的信任域，
  每一次使用都经过 A 的 Agent，也都留在委托链里。

### 2.4 项目技能

- **存放**：项目档案的一部分，`projects/<id>/skills/<名字>/SKILL.md`，和 `files/` 平级。
- **写入**：只经人的操作或档案工具（不变量 17）。
  - 谁能写和项目文件相同：内部项目是所有者，联合项目是主持人。
  - 变更追加到 `log.jsonl`，并在群聊里出一条公开事件（“新增技能：周报写法”）。
- **Agent 能提议，不能直接写**：Agent 觉得某个做法值得沉淀时，用档案工具提交技能**提议**（正文 + 理由）。
  人批准后才进档案，流程同纲要修改建议（`propose_brief` → 主持人采纳或拒绝）。这符合不变量 9（知识只显式共享）。
- **作者与来源**：每个技能显示作者（哪个人，或哪个 Agent 提议、谁批准）和最近修改时间。联合项目里所有参与者都能看到全文：
  它会影响每个人的 Agent，必须公开。
- **不授予任何权限**：技能里写“运行这个脚本”，没有 `shell.exec` 就运行不了；写“去飞书里查”，没有就绪的连接器就查不了。
  技能只是说明，有效权限仍按不变量 1 计算。

## 3. 每一轮 Agent 拿到什么

```
有效连接器 = 所有者授权过的
           ∩ 所有者给这个 Agent 勾上的
           ∩ （联合项目里）所有者在这个项目里打开的
           ∩ 本轮权限含 connector.use（委托可以收窄掉）
           ∩ 运行时能强制只给这些的

技能 = 项目技能（在项目里时）
     + 我的技能里给这个 Agent 勾上的
     + Agent 自己攒的（私有目录挂载时）
```

- **权限**：
  - 新增权限 `connector.use`，按 AGENTS.md 的规定同步三处，`test_authorities_registered_everywhere` 守着。
  - 委托方可以不授予它：被委托方这一轮就没有任何连接器（不变量 1、3）。
  - 不按连接器细分权限：细分会把“谁授权过什么”泄露给委托方。先只做开 / 关。
- **重名**：
  - 网络在挂载前就解决，不交给运行时：**项目技能 > 我的技能 > Agent 自己攒的**。在项目里，大家约定的做法优先。
  - 被盖住的写进这一轮的运行记录，只给 Agent 所有者看。
  - 私聊里没有项目层。
- **提示词**：
  - 只在本轮可用的连接器有变化时，按名字列出（“本轮可用：飞书文档（你的所有者授权）”）。
  - 技能交给运行时自己发现，提示词不重复正文。
  - 文案保持通用，不写领域假设（`test_task_prompt_has_no_domain_constraints` 的精神）。

## 4. 怎么送到运行时（实现层，用户看不到）

### 4.1 技能

工作目录里新增只读的 `skills/`，每轮运行前拷入、运行后丢弃改动（同 `project/`）：

```
<workdir>/
  project/          项目文件（现有）
  agent-home/       私有目录（现有，按挂载规则）
  skills/           本轮生效的技能，已按重名规则合并
    <名字>/SKILL.md
```

- **云端 dsh**：
  - 覆盖层里设置 `- id: skill-filesystem`，配置 `config: {includeDefaultRoots: false, customSkillDirs: [<workdir>/skills]}`。
  - **这同时修掉一个现有漏洞**：现在 dsh 会读部署机器上的 `~/.dsh/skills`、`~/.agents/skills`。
    如果数据目录在某个 git 仓库里，还会读 `.git` 所在目录下的 `.dsh/skills`、`.agents/skills`。
    也就是部署者机器上的技能会进到所有用户的 Agent。
- **我的电脑**：
  - 技能随材料下发。材料要支持子目录（现在只发项目顶层 ≤2 MB 的文件），并给技能单独预算：单个 ≤256 KB，合计 ≤2 MB。
  - dsh 用同样的覆盖层。
  - Claude Code 放到工作目录的 `.claude/skills/`。
  - 其他工具按它们自己的约定放；没有约定的，在提示词里列出名字与描述，正文让 Agent 按需读文件（待验证）。
  - 用户自己电脑上原有的技能是用户自己的东西，不由网络去关，但界面要写明“这台电脑上的工具还会读取你本机的技能”。

### 4.2 连接器

- **目录**：
  - 部署方维护 `connectors.json`（默认 `<data>/connectors.json`），按修改时间热加载，做法同 `models.json`。
  - 每项包括：
    - id、名字、描述。
    - 认证方式：表单字段或 OAuth。
    - 接入方式：远程 MCP、本地 MCP 或命令行，界面不显示。
    - 自带的技能。
    - 支持云端还是我的电脑。
  - 没有这个文件时不提供云端连接器。
- **云端：凭证不进运行时，由网络代调用**：
  - 远程 MCP 类连接器由网络转发：运行时挂的是一个本地 stdio 桥（同现有网络工具的 `mcp_server.py`），
    凭执行上下文令牌回调 `/internal/connectors`。
  - 网络查这一轮的有效连接器，带上凭证转发到外部服务，再把结果返回。
  - 好处：
    - 凭证从不出现在工作目录、覆盖层、进程环境里，沙箱“只管写不管读”的已知风险碰不到它。
    - 每一次调用都在网络这一侧，可以记录、限流、按执行上下文拒绝（不变量 10、11）。
  - 命令行类和本地 MCP 类连接器需要在运行时机器上跑、凭证在本地，**云端不支持**，只在我的电脑上用。
  - 凭证用 `<data>/vault/` 加密保存，主密钥取自 `AGENTNET_VAULT_KEY` 或 `<data>/vault.key`（0600），不进 `state.json`，
    也不进任何事件、日志或 API 返回（安全红线）。
- **我的电脑**：
  - 连接器就是这台电脑上已经配好的服务：用户自己工具里配的 MCP、自己登录过的命令行工具。
  - Matrix 客户端只上报名字与状态。
  - 网络按每一轮的有效连接器告诉驱动“只开这些”，例如 Claude Code 用 `--strict-mcp-config` 加指定配置。
  - **驱动做不到只开指定的那些时，在能力报告里如实标出**（同现有能力报告的做法）。这台电脑上的 Agent 在联合项目里就一律不开连接器，
    内部项目和私聊里在界面写明“由你本机的工具决定”。
  - 以后走 ACP 时，`session/new` 声明 MCP 服务器，这一步能统一（见 [acp-runtime.md](acp-runtime.md)，60 秒超时的限制在那里）。
- **生命周期归人和网络，不归 Agent**：Agent 没有安装、授权、开启连接器的工具。
  以后可以给一个“提议接入某个连接器”的网络工具，效果只是给所有者弹一张卡片（参照 WorkBuddy 的 `suggest_plugin_install`）。

## 7. 和不变量的关系

| 不变量 | 这份设计怎么守 |
| --- | --- |
| 1 权限只收窄 | `connector.use` 进权限交集；项目层不持有凭证、技能不授予权限，进项目不会多出能力 |
| 3 约束累加 | 委托不授予 `connector.use`，下游整条链都没有连接器 |
| 8 私有目录 | Agent 自己攒的技能只在私有目录里，网络不读；技能库在 `users/` 下，和私有目录分开 |
| 9 知识显式共享 | 项目技能只经人写入或经人批准的提议进入，不自动抽取 |
| 10 身份由网络认定 | 云端连接器调用凭执行上下文令牌，网络按令牌查有效连接器 |
| 11 越权留痕 | 对不在有效集合里的连接器的调用被拒绝并记录 |
| 13 无权限即不存在 | 连接器与调用记录只给授权人；别人只看到就绪状态 |
| 16 不跨信任域 | 不做公共授权；联合项目里默认关，要用别人的连接器就委托别人的 Agent |
| 17 档案只走网络 | 项目技能是档案的一部分，写入走 UI 或档案工具，记 `log.jsonl` |

候选新不变量（采纳时写进 invariants.md、补测试、刷新 about.html 架构图，见 AGENTS.md 工作方式 7、12）：

> **19. 连接器凭证只属于授权的人**：凭证不进提示词、事件、日志、API 返回与工作目录；云端由网络代调用，运行时拿不到凭证；
> 联合项目里默认不开，只能由授权人在这个项目里逐个打开。
