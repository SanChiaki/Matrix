页面能做什么（插件申请的 ∩ 看的人本身有的）

读写记录只能读写自己的表 leads（线索）、visits（拜访）；写入按清单校验字段
读档案纲要、有效决定、项目文件、资源引用——本来就对所有参与者可见
发群聊以正在看的人的名义发消息，每次弹确认卡，点“发送”才发
拿不到私聊、项目会话、委托详情、别人的连接器、审批、Agent 设置、登录凭证；不能直接访问外部网络

Agent 能做什么

plugin_records成员 Agent 按表、筛选、关键词查记录（档案类工具，不需要 delegate）
plugin_write新增或修改一条记录，留痕“谁 · 经什么”；Agent 改记录不会引发记录触发
打法sales-intake 已并入项目技能：新线索怎么判断、什么时候报价、交给谁

触发只做一件事：发一条 @ 成员的消息。之后谁做、要不要委托、怎么验收，都走原来的路，网络不替 Agent 派活。

设计
插件的数据怎么走
以人的身份、带权限检查插件 / 触发的路径沙箱挡住的

已知风险：沙箱挡不住插件页面把自己跳转到外部地址、带出它读到的数据，所以桥只给全体参与者本来就看得到的内容。插件要人安装，按版本固定。
