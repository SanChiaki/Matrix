# 项目与项目会话（设计）

> 当前实现要点见 [reference/projects.md](reference/projects.md)，不变量见 [reference/invariants.md](reference/invariants.md)。

## 1. 为什么只有一层

早先是两层：群组带一整套目标性质的档案（brief、决定、文件），项目又在上面套一层同样的东西，人要判断写进哪一层、
理解“挂载”“方面”“提升”这些只为连接两层而存在的操作；Agent 每轮拿两段背景，外加“项目决定为准”的优先级规则。
现在两层收敛为**项目**一层。

已定的取舍：

1. 委托边界就是项目，没有群组这一层。
2. 联合项目里所有参与方看得到项目的全部内容。
3. 纲要（原 brief）默认对项目里的所有人可见。
4. 不做“复制成员 / 模板”。
5. 没有“一个方面由多个群组承担”的用法，方面整个去掉。
6. 人在项目里通过**项目会话**和自己的助理 Agent 私下对话，助理的能力和群聊席位一致。

## 2. 模型

**项目** = 成员 Agent + 人（所有者 / 参与者）+ 一个项目群聊 + 项目档案。

- `internal`（内部项目）只有所有者；`joint`（联合项目，参照 Raft 的 joint channel，research: raft#joint-channel）
  由主持人邀请，参与者接受后各自带上自己的 Agent，档案与群聊对所有参与者可见。创建后不能转换类型。
- 项目档案：**纲要**（目标、范围、成功标准、当前阶段，≤4000 字）、决定、文件、资源引用、纲要修改建议（不变量 17）。
- 委托只发给项目成员；Agent 不跨信任域，委托可以跨（联合项目）。
- 私聊在项目之外。

**助理**：`User.assistant_id`，用户指定的自己的一个 Agent，默认是第一个创建的，可以换。

- 人进项目（创建内部项目、接受联合项目邀请）时，这个人的助理自动成为成员，群聊里记一条事件。
- 人在项目里时助理不能被移出；换助理后新助理在下次进项目或开会话时加入，旧助理留在已有项目里，去留由人决定。
- 人退出 / 被移出时这个人的 Agent 一并移出，在这个项目里的会话归档为只读（本人仍看得到）。

**项目会话**：`Conversation.kind = session`，带 `project_id`、`owner_id`（这个人）、`agent_id`（这个人的助理）。

- 一个人在一个项目里可以有多个，命名、归档；只有这个人看得到（联合项目里其他参与方看不到）。
- 每个会话是一个独立席位（独立会话、工作目录，不变量 7），能力和群聊席位一致：委托项目成员、登记用户任务、用档案工具。
- 影响共享状态的写入（决定、文件、纲要修改建议）在项目群聊里记一条事件，参与方不会被蒙在鼓里。
- 会话里登记的用户任务属于这个项目、照常上看板，可见性不变（下发人 + 接任务 Agent 的所有者）。

分工：**群聊是项目的公开记录**（要让大家看到的交代、讨论、结论），**会话是一个人的私下工作区**（了解细节、想清楚、让助理代办）。

## 3. 会话携带的上下文

1. 项目档案：和群聊席位一样按 `archive_rev` 推送，文件放在只读的 `project/`。
2. 有上限的现状快照：成员、没结束的用户任务、最近的群聊公开消息，条数与字节封顶，只在变化时重新推送
   （参照 xMatrix 启动时只给有界历史，research: xmatrix#context-isolation）。
3. 只读网络工具：`read_chat`（按关键词读群聊的一段）、`read_request`（用户任务与它的委托、交付说明）。

助理读到的一切按**它的所有者**在这个项目里的可见性过滤（不变量 18）：联合项目里别人 Agent 的过程、只给两端所有者的委托，助理同样读不到。
私有目录挂载沿用项目设置（联合项目默认不挂）：会话里只有自己在说话，但快照和读工具会带进合作方的内容。

## 4. 去掉的东西

| 以前 | 现在 |
| --- | --- |
| 项目（汇总层）、方面、挂载 / 移出 | 没有；一个项目就是原来的一个群组 |
| 群组档案 + 项目档案、两段背景、“项目决定为准” | 一份项目档案 |
| 项目文件的提升、`publish_file target=group/project` | 只有项目文件 |
| 跨群组交接（依赖、替换、交回） | 项目内委托：协调的 Agent 依次委托、靠收件箱唤醒等交付 |
| 负责人统筹、停滞提醒 | 被 @ 的 Agent 协调，直接委托方验收（不变量 5）；委托链禁止成环（不变量 4），互等形成不了 |
| 项目文件共享给联合群组 | 联合项目全可见 |

接受的代价：中间环节不上看板（在任务详情里看）；协调的 Agent 需要 `delegate`；群聊噪音随成员增长；
委托次数默认不限制，需要时由所有者在 Agent 设置里设上限（`max_delegations`）；联合项目里合作方 Agent 能直接委托你的 Agent
（外溢审批仍找所有者）。

## 5. 旧数据迁移（`Store._load`，测试见 `tests/test_migration.py`）

- 迁移前的 `state.json` 原样另存为 `state.v1.json`。
- 没挂项目的群组 → 项目，无损；`groups/<id>/` → `projects/<id>/`。
- 挂了多个内部群组的旧项目 → 合成一个项目：成员取并集；纲要、决定、文件以旧项目为准，各群组的带上来源标注（文件重名加前缀）；
  最近活跃的群聊留作项目群聊，其余归档为只读。
- 挂在旧项目里的联合群组单独成为联合项目（不同信任域，不合并），带上原来共享给它的项目文件。
- 未完成的交接作废并在群聊里记事件；负责人设置丢弃；`UserRequest.project_id` 指向新项目，方面丢弃。
- 已有用户的助理取最早创建的 Agent；已有项目里不在加载时加 Agent，等人第一次开会话时再加并记事件。
