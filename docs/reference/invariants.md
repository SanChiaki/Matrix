# 网络不变量

> 改代码时必须保持，均有测试覆盖：测试 docstring 写“不变量 N”，`test_invariants_have_tests` 对照本文件。
> [AGENTS.md](../../AGENTS.md) 里有每条的一行索引，增删或改编号时两边一起改（同一个测试会检查）。

1. **权限只收窄不放大**：执行者有效权限 = 执行者自身权限 ∩ 委托授予；授予只能来自委托方的有效权限。
   还要再交**运行时能强制的权限**（`RuntimeCapabilities.enforces`）：做不到的不进入有效权限，
   记进 `Task.narrowed` 并写明原因。见 `docs/device-runtimes.md` 第 3 节。
2. **只委托项目成员**：目标不在项目里即拒绝（`REJECTED`）。网络不自动创建 Agent（CHARTER 第六节第 4 步
   "寻找或创建相关 Agent" 以"Agent 起草、人提交"的方式落地）：Agent 用 `propose_agent` 提议，提议的权限不能超出
   提议者当时的有效权限；人审核（可修改，权限仍受同一上限约束）后以人的身份创建，加入提议发生的项目，长期存在，
   人可删除。提议结果作为通知唤醒提议者。不要让 Agent 绕过人直接创建 Agent。
3. **约束沿委托链累加**，子任务继承全部上游约束。
4. **防环与限深**：目标已在委托链上则拒绝；深度达到 `max_depth`（默认 3）时移除 `delegate`、不挂载网络工具；
   委托次数上限是委托方 Agent 自己的设置（`Agent.max_delegations`，默认不限制）：设了时，每次被 @ 引出的工作（席位）/
   每个任务最多委托这么多次，跨轮次累计；不能委托给自己。
   每个任务最多退回 `max_revisions`、续接 `max_retries` 次（默认各 3）。
5. **只有直接委托方能验收**：`accept_task` / `request_changes` / `retry_task` 只对自己在当前上下文发起的任务有效。
6. **协作只走网络**：系统中可见的 Agent 之间的协作必须经过网络工具（`delegate` / `share_knowledge` 等）。
   Agent 在自身运行时内使用 subagent / workflow / goal 等属于它自己的作用域，网络不加控制也不记违规；
   子 Agent 共用父 Agent 的插件覆盖层与沙箱，权限不会超出父 Agent。只有 `tool-plugin-manager`
   （可在运行期重新启用插件、绕过权限覆盖层）始终禁用。
7. **上下文默认隔离**：每个席位、每个委托任务独立会话、独立工作目录；后续轮次（唤醒、返工、续接）续接各自的会话。
   群聊里成员之间只共享公开消息，委托内部的内容不进群聊；项目会话的内容不进群聊。
8. **私有目录归 Agent 自己**：`agents/<id>/` 每次运行挂载到工作目录的 `agent-home/`（运行前拷入、运行后同步回去），
   网络不为自己读取、不注入提示词，只按不变量 22 决定挂哪些文件、代 Agent 本人用 `open_note` 取出没挂上的笔记并记下来源；
   没有 `file.write` 时只读。
9. **知识只显式共享**：结果只对产生者与直接委托方可见，其余必须通过 `share` 或 `share_knowledge`，且只能共享自己可见的知识。
10. **身份由网络认定**：调用方由运行期间才有效的执行上下文令牌识别，不信任模型自报身份。用户任务代验收只认本轮送达、@ 当前席位的下发人消息，验收语义由模型判断。
11. **越权必留痕**：工具调用与权限不符时写入 `task.violations` 并发出 `authority.violation` 事件。
12. **重启语义**：重启后对话回到 `idle`（席位收件箱保留）；运行中的**云侧**任务标记为 `FAILED`，失败通知进委托方席位或
    上级任务的收件箱，可续接；待审批的外溢申请作废（那次运行已随重启结束）。**端侧**任务回到 `WAITING`（不判失败；
    `Store._load` 按 `delegatee.device_runtime` 区分），端侧上线后继续。
13. **归属与可见性**：用户只看得到自己主持或参与的项目及其群聊、自己的项目会话与私聊、自己的 Agent（和同在一个项目里的别人的
    Agent 的名片）。委托只给两端 Agent 的所有者；有别人的项目里过程、失败说明、外溢申请只给 Agent 的所有者；提议给提议者 Agent 的所有者；
    知识随产生它的委托。无权限一律按“不存在”（404）处理。SSE 推送前按用户过滤并裁剪（`Network.event_view`）。
    引擎方法的 `actor=None` 表示系统内部或测试，不做检查；HTTP 层必须传入当前用户。
14. **工作区外溢由所有者批准**：dsh 沙箱拒绝工作目录以外的写之后，模型可以申请升权重试一次；申请经 `dsh_plugins/approval.mjs`
    转到 `/internal/approval`，交给 **Agent 的所有者**（不是发起对话的人）。获批只对那一次调用生效；云侧超时
    （`approval_timeout_s`）作废，**端侧不按时间作废**，只在设备断连时结束。
15. **并发不抢占**：同一 Agent 可同时做多件事（包括在有别人的项目里被别人 @）。每轮提示词带工作台账（`Network.ledger`）；私有目录写回时按文件三方合并，
    期间被别的运行改过的文件不覆盖，另存 `*.conflict-*` 副本。
16. **Agent 不跨信任域**：Agent 只属于所有者，只有所有者能用它（私聊、拉进项目）、改它；它只代表所有者运行。跨用户协作只能通过项目：
    项目没有类型，有参与者或待接受的邀请就是共享的（`Project.shared`），任何项目都能邀请；第一次邀请时群聊席位换新会话。
    共享项目里工作台账不列出别处工作的细节；端侧 Agent 还没有来源标签，共享项目里私有目录不挂载。
17. **项目档案只走网络**：档案是项目页上的说明（纲要、已定的事）、资料（文件、链接）、项目技能与连接器面板里主持人手动维护的部分
    （手动添加的服务、给链接指定的服务）。写入只能经人的操作或档案工具，变更追加到 `projects/<id>/log.jsonl`，公开变化写进群聊；
    运行时拿到的是只读副本（`project/`）。推送部分有预算（纲要 ≤4000 字，最近 12 条有效决定）。
18. **项目会话只属于它的人，助理按所有者的可见性读取项目状态**：项目会话（`kind=session`）只有开它的人看得到，
    联合项目里别的参与方看不到、收不到它的事件；助理在会话里推送到的项目现状与 `read_chat` / `read_request` 读到的内容，
    都按会话主人在这个项目里的可见性过滤（只给别人看的消息、看不到的用户任务与委托一律读不到）。会话里只能 @ 会话主人
    自己的 Agent（没 @ 时交给助理），别人的 Agent 不进会话。人在项目里时，
    其助理自动加入、不能被移出；人退出项目时，其会话归档为只读。
19. **连接器凭证只属于授权的人**：凭证只进加密保管（`vault/`），不进 `state.json`、提示词、事件、日志、API 返回与任何工作目录；
    云端连接器由网络凭执行上下文令牌代为调用，运行时拿不到凭证，调用这一轮没有的连接器被拒绝并留痕。连接器与调用记录只给授权人。
    共享项目里授权人对自己的每个连接器选“用到时问”（默认）/“这个项目里都可以”/“不行”（`Project.connector_grants`，只有授权人看得到、能改）：
    用到时问的，这一轮第一次调用先停下等授权人决定（只这一轮 / 以后这个项目里都可以 / 不行），不理会按不行；
    电脑上的服务由那台电脑上的 AI 工具直接调用、网络拦不到，只有“都可以”才给。部署方目录里的连接器，工具按 MCP 标注
    （annotations）明确是写操作并且 `destructiveHint` 或 `openWorldHint` 为真的，**每次调用**都先给授权人一张确认卡，
    照原样列出网络要发出的参数，同意才发、只发这一次，不理会按不发（`Approval.kind = "connector_write"`；只认明确的标注，
    只信部署方目录里的服务）。项目的连接器面板只列出用到了哪些服务
    （资料里的链接、插件声明、实际调用、手动添加）和成员的就绪状态，不持有凭证、不给是谁的账号；
    要用别人的连接器就委托别人的 Agent。详见 [connectors-skills.md](connectors-skills.md)。
20. **插件页面代码只在浏览器沙箱里，只经网络、以看的人的身份读写**：插件页面跑在不透明来源的 iframe 里（`sandbox="allow-scripts allow-forms"`
    + CSP `sandbox allow-scripts allow-forms; connect-src 'none'; form-action 'none'`），拿不到登录凭证、不能直连网络；帧令牌只取这个插件 `page/` 下的静态文件，
    过期、换版本、停用、卸载、看的人看不到项目时一律 404；停用的插件对页面、Agent 与触发一律不可用。读写只经父页面的桥，能力 = 插件申请的 ∩ 看的人本身有的，读范围不超过
    项目里全体参与者可见的内容；以看的人名义发群聊只生成草稿，由这个人在父页面的确认卡上发出。插件数据是项目档案的一部分
    （不变量 17）；Agent 写记录不引发记录触发（不变量 6）；触发只往群聊发消息、代表启用它的人，不派委托。
    页面代码不在服务器和运行时里执行；服务端的插件代码只有不变量 24 的插件服务一条路。页面调插件服务只能调只读工具（`service.call`）。
    详见 [plugins.md](plugins.md)。
21. **助理对话只替主人读与起草，读到共享项目内容的那一轮不能调用连接器；定时只属于主人**：助理对话（和当前助理的私聊）推送的跨项目总览、助理对话里的读工具都按主人的可见性过滤（同不变量 18），只有主人看得到；往项目里说话只能起草（`draft_message`），由主人在确认卡上发出，发出的消息以主人的身份、带 `via`。这一轮送来了共享项目里合作方写的新内容、或读工具读了共享项目，这一轮就不挂、不代调用连接器（`ExecContext.tainted`，是收窄不是越权，不记违规）。定时只属于创建它的人、只唤醒他自己的 Agent，全部在一处可见、可停、可删，有个数与每天次数上限；定时轮次没有下发人，不能登记用户任务（不变量 10）。详见 [assistant.md](assistant.md)。
22. **信息只流向当时在场的人**：网络在写回私有目录时给每个文件记下写它的场合（项目，或只有所有者在场的 `me`）与这一轮读过的来源
    （`<data>/flow/<agent>.json`，Agent 写不到；没有标签的老文件按 `me`）。场合在场的人 = 项目现在的参与者 + Agent 的所有者。
    一轮运行只挂技能和“在场的人包含这一轮输出能到达的人”的文件，其余只列名字，用 `open_note` 读；读了，那些场合记进这个模型会话的来源
    （`session_sources`，会话重开才清空）。这一轮还能联网、执行命令、用连接器时 `open_note` 只排到下一轮，来源越界的会话去掉这三种能力。
    群聊回复与委托交付的听众不全在每个来源场合里、又没有所有者的授权（`Project.flow_grants`）时拦下（`Held`），只有 Agent 的所有者能
    发这一次 / 发出并授权 / 让它换新会话重写；会让别人看到内容的网络工具直接拒绝（收窄，不记违规）。有别人的场合里技能改动不写回，
    没挂上的文件被同名写出时另存冲突副本。连接器读到的内容不另记来源：共享项目里调用之前已经问过授权人（不变量 19），
    授权人知道回复会给谁看。判断只是标签上的集合比较，不用模型、不看内容。详见 [projects.md](projects.md)。
23. **发布只经主持人，交付件只流向读者**：项目的内容离开项目只经发布物（`Release`）：只有主持人发布、改读者、切版本、撤回，
    或者主持人对一份交付件开的“跟随档案”（范围固定为那几个文件 + 那份读者名单）在文件更新时由网络切版本；每个版本固定成快照
    （`releases/<id>/v<N>/`），发布、新版本、撤回都写 `log.jsonl` 并在群聊里公开记录。技能包（一组技能）可以给点名的读者或所有登录用户，
    交付件（档案文件，可带插件视图）只给点名的读者；项目参与者总是看得到，其他人一律按不存在（404）。订阅只能由人勾给自己的 Agent，
    只在这一轮输出能到达的人（`_reach`）都看得到这份发布物时生效：技能包进技能层，交付件只读挂到 `releases/<名字>/`，否则只在提示词里
    说明没挂上；运行用订阅者自己的资源与授权，发布物不带发布方的凭证；发布方只看得到订阅数。发布物里的插件页面是发布时快照的代码，
    令牌绑定读者 + 发布物 + 版本，桥只读快照（不变量 20 的沙箱照旧）。读者只读，反馈只有读者自己写的文字，以群聊事件回流，
    不唤醒成员。详见 [releases.md](releases.md)。
24. **插件服务只来自部署方目录，只经网络、按挂点作用**：带 `service` 的插件只能从部署方目录安装，主持人上传的包带 `service` 一律拒绝。
    网络按安装（项目 × 插件）托管一个 stdio MCP 进程（`matrix/plugin_service.py`），工作目录是这个安装的数据目录
    （`plugin-data/<插件>/service/`，项目档案的一部分，卸载不删），环境里只有运行程序必需的变量，不带任何凭证、令牌与密钥；
    停用、卸载、升级时停掉进程。插件只经清单声明的挂点影响运行：工具（`plugin_tools` / `plugin_call`，网络工具通道，只开清单白名单里的，
    读写分级；写类要 `file.write`，按不变量 22 会让当时不在场的人看到的不放行）、`mount`（数据只读挂进 `plugins/<插件>/`）、
    `context`（提示词里加一段标明来源插件的内容，有预算）、`after`（项目群聊里的用户任务验收之后，代表验收的人 @ 成员或由网络调工具；
    项目会话、私聊里的任务不触发），只对装了它的项目里的运行生效，助理对话、私聊、别的项目都没有。工具调用的身份由网络认定、
    每次留痕（不记参数与结果），服务看到的只是参数；插件不能改变其他安全类不变量规定的任何结果。详见 [plugins.md](plugins.md)。
