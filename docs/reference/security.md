# 安全边界

> 入口见 [AGENTS.md](../../AGENTS.md)，那里只列红线。

- `/api/*` 要求登录（邮箱 + 密码，`auth.py`，HttpOnly + SameSite=Lax cookie），按用户做归属与可见性检查。
  这仍是最简实现：没有 HTTPS、CSRF 令牌、登录限流、令牌过期、邮箱验证。服务只监听 `127.0.0.1`，不要暴露到公网或改成 `0.0.0.0`。
- 密码只存 scrypt 哈希；不要在日志、事件或 API 返回里带出密码、哈希、登录令牌。`/api/users` 只返回 id 与邮箱。
- `/internal/tools`、`/internal/approval` 只能凭有效执行上下文令牌调用，不走登录；不要放宽这一校验。
- **网络管关系，不管 Agent 在自己环境里能碰什么**。云侧 Agent 的读隔离目前做不到（见下一条）；端侧 Agent
  读的是所有者自己的机器，不在网络管辖范围，网络只对经过它的协作工具负责。共享项目里端侧 Agent 会把群聊内容
  带到成员的机器上——这是已接受的披露（与"档案对所有参与方可见"同一逻辑），UI 要标出成员所在位置。
- **已知风险（接受）：沙箱只管写、不管读**。任何 Agent 的运行时都能读到整个 `--data` 目录（别人的私有目录、对话、任务、项目档案）。
  信任域隔离（不变量 13、16）目前只在提示词、网络工具与 API 层成立，文件层挡不住；共享项目会放大这个风险（别的参与者可以 @ 诱导读取）。
  接受理由：本地单机 Demo、所有用户在同一台机器上；范围：DSH 运行时；复查时机：接入第二个运行时或任何多机部署之前，必须先做读隔离。
- **信息流（不变量 22，[projects.md](../projects.md) 第 6 节）**：私有目录按来源场合挂载，用到别处资料的回复与交付先给所有者确认，
  判断只比对标签，不用模型。**已知风险（接受）**：
  - 读隔离之前，被诱导的云侧模型可以绕过 `open_note` 直接读 `--data` 下的私有目录（同上一条），规则只挡得住“没有主动绕路”的 Agent；
  - 没挂上的笔记的文件名出现在提示词里，不算来源，可能被说出去；
  - 按会话整体判定，读过没用上也会拦，所以确认卡会重复出现（卡片上有“以后在这里都能用”）；
  - 在场的人按项目现在的参与者算，后来加入的人看得到以前在这个项目里写的笔记（第一次邀请前的确认框写明）；
  - 端侧 Agent 没有来源标签，共享项目里私有目录不挂。
  复查时机：做读隔离、或端侧接入来源标签时。
- **管理后台**（[admin.md](admin.md)）：管理员由部署方按邮箱指定（`--admins` / `MATRIX_ADMINS`），没指定时是最早注册的人——
  多用户部署要显式指定，不要靠“谁先注册”。后台只看用量不看内容：统计与用量台账里没有项目名、Agent 名、消息正文与提示词，
  非管理员按不存在（404）处理。
- 项目档案文件经 `/api/projects/<id>/files/<name>` 一律以附件下载（`nosniff`），不在本站点内渲染；文件名经 `_safe_filename` 只取最后一段。
  对话附件（`/api/conversations/<id>/attachments/<sha>`）同样以附件下载，上传、下载都先查对话可见性；上传的内容按大小上限流式截断（413）。
- 没有 `file.write` 的 Agent 运行在只读沙箱；有则只能写自己的工作目录。不要绕过 `build_patch_yaml` 生成的限制，
  也不要让审批应答者自动批准：工作目录以外的写只能由 Agent 所有者逐次批准。
- **连接器凭证**（不变量 19，[connectors-skills.md](connectors-skills.md)）：只存在 `vault/<连接 id>.bin`（Fernet 加密，0600），
  主密钥取 `MATRIX_VAULT_KEY`，没有就用 `<data>/vault.key`（0600）。密钥和数据在同一台机器上时只防“数据目录被拷走 / 误提交”，
  防不了能读这台机器的人；而沙箱只管写不管读，云端 Agent 的运行时理论上能读到 `vault.key` 与 `vault/`——
  部署时应当用环境变量给密钥，读隔离做好之前不要在多用户部署里接真实账号。凭证只在网络进程里代调用时解开，
  不进运行时的环境、覆盖层与工作目录；API 只回连接的名字与状态，试连失败的错误信息不含填的值。
- **连接器地址**：目录里的来自部署方的 `connectors.json`，由部署方负责；用户自定义的只能是 https 公网地址，解析出的每个地址都要是公网、直连校验过的 IP（防 DNS 重绑定）、不跟重定向、不走代理（`mcp_client.check_public_url` / `public_only`），避免把网络当跳板访问内网（SSRF）。
- **电脑上的连接器**是用户自己机器上已经配好的服务，网络只拿名字。驱动按这一轮允许的名字只开那些（Claude Code 的临时配置文件 0600、
  在工作目录以外，跑完删掉）；能力报告里不能强制的 AI 工具，Agent 拿不到 `connector.use`。
- **项目插件**（不变量 20，[plugins.md](plugins.md)）：插件代码只在浏览器里跑，网络不在服务器和运行时里执行它。页面是
  `sandbox="allow-scripts allow-forms"`（没有 `allow-same-origin`）的 iframe，响应头再带 CSP `sandbox allow-scripts allow-forms; connect-src 'none'; form-action 'none'; frame-ancestors 'self'`
  （`allow-forms` 只为让表单的 submit 事件触发；`form-action 'none'` 让表单哪里都提交不出去，不多开一条外带通道），
  直接打开地址也在沙箱里：不透明来源，拿不到登录 cookie，`fetch` / XHR / WebSocket 被挡；帧令牌是 HMAC、10 分钟、绑定看的人与版本，
  只取 `page/` 下的文件。桥只做清单申请的 ∩ 看的人本身有的事，以人名义发言必须在父页面确认卡上点发送。
  回调地址的令牌只存 sha256、每分钟限 60 次、请求体 ≤64 KB；触发代表启用它的人，不派委托。
  **已知风险（接受）**：沙箱禁了弹窗与顶层跳转，CSP 禁了主动联网，但挡不住 iframe **自己跳转**到外部地址（把读到的数据编进 URL）——
  浏览器没有可用的 `navigate-to`。所以装了插件，等于把桥允许读的数据交给插件作者。接受理由：只有主持人能装，安装时群聊里公开写明申请的能力；
  复查时机：开放插件市场或允许非主持人安装之前。
- **助理对话**（不变量 21，[assistant.md](assistant.md)）：共享项目里合作方写的内容会进到主人的助理的提示词。那一轮不挂、不代调用连接器，往项目里说话只能起草、主人确认才发，定时轮次不能登记用户任务。
  **已知风险（接受）**：一轮中途才读到共享项目时，只挡得住网络代调用的云端连接器；电脑上的连接器在这一轮开始时已经交给驱动，挡不住。另外 dsh 会话会续接，读过的共享项目内容留在后面几轮的上下文里，之后的轮次只按“这一轮有没有送来新的共享项目内容”判断。接受理由：连接器默认只在主人自己的项目里用，共享项目内容在提示词里标明是参考；复查时机：给连接器开写操作的自动放行、或助理对话接入端侧运行时之前。
- **技能**：覆盖层总是关掉 dsh 的默认技能根，部署机器上的技能不会进到用户的 Agent；技能文件的路径经 `skills.safe_rel` 校验，
  不能跳出技能目录、不能以点开头。
