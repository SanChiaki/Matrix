# 对话：项目群聊、项目会话、私聊与共享项目

> 入口见 [AGENTS.md](../../AGENTS.md)。可见性规则以 [invariants.md](invariants.md) 第 13、16 条为准。

## 群聊：被 @ 的成员接任务

参照 Raft（botiverse/raft）的频道模型（research: raft#channels-dm）：

- 人发的消息里 @ 到的项目成员（`@名称`，长名字优先匹配；或 API 的 `mentions`）被唤醒，在自己的席位上处理。它自己做，或在项目里找合适的成员委托。一条消息可以 @ 多个成员，各自的席位并行处理。
- 没 @ 任何人的消息留在群聊里，不唤醒任何人；只能 @ 项目成员。例外：项目装了带 `route` 挂点的插件时，插件可以建议叫谁来看、
  谁来认领，网络按预算、链、只看群聊、认领规则过闸门后唤醒（[plugins.md](plugins.md)“route 挂点”，不变量 24）。
- 席位被唤醒时收到**上次运行之后群聊里的新公开消息**（人的消息、其他成员的回复），其中 @ 它的那条标为“@ 你”。委托的过程、结果、知识不在公开消息里，只送给委托方（不变量 9）。
- 委托回报回到委托方的席位（或上一级任务），由它验收。执行者工作目录里的**产物**（除去运行时文件、只读副本、`tmp/`、缓存）
  在交付时快照进委托方工作目录的 `deliveries/<task_id>/`（`matrix/workdir.py`），重新交付时整体替换。
  Agent 的所有者可以在 UI 里浏览、下载自己 Agent 的席位与任务工作目录（只读）。
- **附件**（参照 dsh，research: deepseek-harness#attachments）：人先把文件上传到对话（`POST /api/conversations/<id>/attachments`，
  请求体就是文件内容，单个 ≤20 MB），再随消息发出（`Message.attachments`：sha、name、size、mime）。文件按 sha256 只读存在
  `<data>/attachments/<对话>/`，不在任何席位工作目录或私有目录里。席位每轮把它看得到的消息上的附件拷进工作目录的
  `attachments/<sha 前 8 位>/<文件名>`（只读副本，同 `project/`，运行后丢弃，不算产物），新消息里每个附件一行路径，模型用自己的工具读；
  端侧随 `run.request.materials` 下发。进委托任务只能由委托方用 `delegate` 的 `attachments`（每行一个路径）显式转交。
  上传、下载按对话可见性，看不到的一律 404（不变量 13）；下载一律以附件返回。不按文件类型区分，图片也是普通文件。
- 群成员随时可以加减（`POST /api/projects/<id>/members`、`DELETE …/members/<agent>`），变动作为 `event` 消息写进群聊，
  之后被唤醒的成员也能看到。移出项目不打断已经接下的任务，只是不能再被 @、被委托。
- 群聊、私聊不能删除，只能清空记录（`/clear`，席位会话从头开始，委托与知识不受影响）；只有归档的对话可以删除。
- 旧版对话（一个“主 Agent”）加载时迁移为只有这一个席位的群聊（原来在项目里）或私聊，沿用原会话与目录。
  旧版同一个项目 / Agent 有多个对话时，最近活跃的那个成为正式群聊 / 私聊，其余归档为只读（`Store._one_chat_each`）。
- 旧版 public / shared Agent 加载时（`Store._one_trust_domain`）：别人和它的私聊归档为只读；内部项目里不属于项目所有者的 Agent
  移出，群聊里记一条事件；已有委托与记录保留。

## 项目会话：一个人和自己的助理

- 人在项目里想了解细节、想清楚一件事时，不在群聊里发，而是开一个项目会话（`kind = session`）：默认对话方是这个人的助理，没 @ 的消息直接交给它；
  也可以 @ 自己在项目里的其他 Agent，直接交给它（成员列表只有自己的 Agent，别人的 Agent 不进会话，要找它们去群聊）。
- 只有会话的主人看得到（不变量 18）；会话不进群聊，但助理在会话里写档案（决定、文件、纲要修改建议）照常在群聊里记事件。
- 实现要点见 [projects.md](projects.md)。

## 共享项目：跨用户协作只走这里

参照 Raft 的 joint channel（research: raft#joint-channel）：**Agent 不跨信任域，委托可以跨**。共享的是对话空间（群聊 + 项目档案），不共享 Agent。

- 项目没有类型：主持人在任何项目里都能按邮箱邀请（`POST /api/projects/<id>/invitations`），对方在“待我处理”里接受或拒绝。接受前只看得到项目名、描述、主持人。
  有参与者或待接受的邀请就是共享项目（`Project.shared`）；第一次邀请时群聊席位换新会话（`_start_sharing`）。
- 每个参与者只能加减自己的 Agent；主持人能移出任何 Agent 与参与者。参与者退出 / 被移出时这个人的 Agent 一并移出（已接下的任务照常完成），
  之后看不到项目与群聊，自己在项目里的会话归档为只读。主持人不能退出，只能删除。改名、纲要、资源引用、清空群聊、删除项目只有主持人能做。
- 任何参与者能 @ 任何成员。被 @ 的 Agent 仍**以它的所有者的名义、用所有者的资源**运行：外溢审批找它的所有者，提议由它的所有者审核。
- 可见性（不变量 13）：人的消息、Agent 的最终回复、成员与档案事件对所有参与者可见；Agent 回复的过程（`steps` / `wake`）、运行中的进度、
  席位失败说明、外溢申请只给这个 Agent 的所有者；委托（详情、看板、事件）只给两端 Agent 的所有者（`Task.owners`）。
- 私有目录照常挂载，但只挂技能和能给这里的人看的笔记；用到别处资料的回复与交付先给所有者确认（不变量 22，[projects.md](projects.md)）。
  端侧 Agent 在共享项目里不挂私有目录。
- 工作台账在共享项目里只列同一项目的条目，其余只给数量（不变量 16）。
